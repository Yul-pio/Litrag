# 检索评测

## 为什么必须评测

没有评测的 RAG 只能靠感觉调参。改动分块大小、换检索算法、加同义词，都需要一个固定的题集来判断效果是变好还是变坏。评测集也是团队协作的基础：两个人对同一个改动有分歧时，跑一遍题集就能得出结论，而不是靠嗓门。

## 常用指标

Recall@k 衡量前 k 个召回结果里是否包含正确文档，是最直观的指标。MRR 是平均倒数排名，它关注正确结果排在第几位，排名越靠前分数越高，因此对「第一条就命中」特别敏感。如果下游还要生成回答，通常还会补充人工评分或模型评分来评估回答的忠实度。

## 评测集的构造

评测集由问题和标准答案组成。标准答案不一定是完整回答，可以只标注正确文档或关键片段，这样标注成本低，也足够衡量检索质量。规模不必大，五十到一百条就能看出趋势。关键是题目要覆盖真实用户的提问方式，而不是只覆盖文档里出现过的原句，否则指标会虚高。
