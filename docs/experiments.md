# 实验报告：把「看起来能用」的 RAG 变成「可验证」的 RAG

> 项目：litrag —— 面向学术文献的检索增强问答
> 时间：2026 年 10 月
> 结论先行：四组对照实验，把 46 题开发集的 Recall@1 从 78.3% 提到 93.5%，
> 把不可回答题的误答率从 55% 降到 15%，每一步都有可复现的数字。

---

## 0. 一句话背景

通用大模型回答学术问题有两个硬伤：不知道你的私有文献，以及会编造引用。
本项目的做法是**确定性 RAG**：检索 → 判断能不能答 → 只摘原文 → 标页码。
不接大模型也能跑，接入后只是把摘录组织得更顺，不改变「每条结论必须有出处」这条约束。

---

## 1. 系统结构

```
PDF ──loader──> 文本（按页）
        │
    chunker     按标题分节 → 段落合并 → 超长按句切 → 相邻重叠
        │
    bm25        单字+双字切分，标题进索引
        │
    retriever   打分 → 别名加权 → 取 top-k
        │
    answerer    可答判断 → 摘句 → 引用
        │
    回答 + [n] 页码
```

离线两件事：解析、建索引。在线两件事：检索、回答。
把重的放到离线，是在线快的前提。

---

## 2. 实验一：块大小与重叠

### 问题

切块大小直接影响两件事：块越大，上下文越完整但噪声越多；块越小，匹配越准但句子容易被切断。
这个参数必须用数据定，不能拍脑袋。

### 做法

固定其它变量，只改 `--chunk-size`，在 46 题开发集上跑 Recall@k 与 MRR。

### 结果

| 块大小 | 块数 | Recall@1 | Recall@3 | MRR |
|---|---|---|---|---|
| 150 | 2744 | 78.3% | 93.5% | 85.9% |
| **200** | **2266** | **84.8%** | 97.8% | **90.9%** |
| 250 | 1905 | 82.6% | 95.7% | 89.3% |
| 320 | 1494 | 80.4% | 97.8% | 88.8% |
| 500 | 920 | 82.6% | 95.7% | 89.3% |
| 800 | 590 | 82.6% | 95.7% | 89.2% |

固定 200 时改 overlap：

| overlap | Recall@1 | Recall@3 | MRR |
|---|---|---|---|
| 0 | 84.8% | 91.3% | 89.2% |
| 30 | 80.4% | 95.7% | 88.2% |
| **60** | **84.8%** | **97.8%** | **90.9%** |
| 90 | 80.4% | 97.8% | 88.8% |
| 120 | 84.8% | 95.7% | 90.8% |

### 结论与局限

- 200 / 60 在 Recall@1 与 MRR 上最好，定为默认值
- **46 道题里一道题 = 2.2 个百分点**，所以 1~2 道题的差异不能断言显著
- overlap=120 反而下降，推测是块间重复变多、挤占了 top-k 的多样性

## 3. 实验二：拒答规则（收益最大）

### 问题

系统必须能说「资料里没有」。否则用户问什么它都能凑一段，看起来就在胡编。

旧规则：取前 3 块，算问题实词被覆盖的比例，低于 20% 就拒答。
在 20 题不可回答集上，**误答率 55%**。

### 诊断

「前 3 块」是个错误抽象：3 段文本拼起来总能凑出几个查询词。
真正会被用来回答的只有**第 1 名那一个块**。

### 做法

换成两个特征取「或」：

| 特征 | 含义 | 阈值 |
|---|---|---|
| `cov_top1` | 第 1 名块覆盖了多少查询实词 | ≥ 0.34 |
| `top_score` | 第 1 名的 BM25 原始分 | ≥ 20 |

加第二个条件的理由：中文短语料库 BM25 分数天然更高（中位数 40 vs 论文的 17），
只按覆盖率会把中文问题大量误杀（通过率掉到 58%）。

### 结果

| 规则 | 能答通过（88 题） | 中文示例（20 题） | 误答 dev（20） | 误答 test（20） |
|---|---|---|---|---|
| 旧：覆盖率 20%（前 3 块） | 100% | 75% | 50% | **55%** |
| **新：cov_top1 ≥ 0.34 或 score ≥ 20** | 92% | 95% | 10% | **15%** |

### 实验设计上的一个关键动作

原来那 20 题已经用来扫过阈值，**不能再用它报成绩**。
所以阈值定下来之后，另写了 20 道全新的不可回答题做冻结测试集，只跑一次。

这是这份报告里最容易被忽略、但最能体现方法严谨性的一步。

### 局限

- 规则不是模型。`top_score ≥ 20` 依赖语料规模，换语料要重新校准
- 剩下 15% 的误答无法靠调阈值解决。典型例子：
  问「What is the capital of Brazil?」，`capital` 命中、`brazil` 没命中，
  覆盖率 50% 刚好过线 —— 词面匹配不知道「Brazil」不该由这篇论文回答
- 试过三种更严的规则，都会把能答通过率从 92% 打到 27%~65%，不划算

### 补救

判成「能答」但证据偏薄时（覆盖率 < 60% 且分数 < 20），回答下方显示：

> ⚠ 匹配度偏低（覆盖率 50%、最高分 14.0），请核对引用原文

宁可承认不确定，也不假装确定。

## 4. 实验三：文档别名加权

### 问题

46 题里有 7 道没排第一，其中 5 道是同一类：
**问某篇论文，综述却排在它前面。**
因为综述大段讨论了这篇论文，词面上比原文还密集。

### 做法

`data/doc_aliases.json` 给每篇文档列别名，问题里出现就给该文档的块加权：

```json
{
  "2310.11511": ["self-rag", "self rag"],
  "2002.08909": ["realm"],
  "2004.04906": ["dpr", "dense passage retrieval"]
}
```

命中 → 该文档所有块分数 ×1.3。

### 结果

| 评测集 | 加权前 Recall@1 | 加权后 Recall@1 | MRR |
|---|---|---|---|
| 46 题开发集 | 84.8% | **91.3%** | 90.9% → 94.6% |
| 20 题 hold-out | 95.0% | **100%** | 96.0% → 100% |
| 拒答 test 误答 | 15% | 15% | 不变 |

boost 取值扫描：0 → 85%，0.3 → 91%，0.5 → 93%。取 0.3 是保守选择。

### 局限

- 别名手工维护，只适合小规模、已知语料
- 试过从 PDF 首页自动提取标题，结果一半是 `arXiv:2002.08909v1 [cs.CL]`、
  「Preprint.」或字母被拆开的标题，质量不稳，回退到手工表
- `survey` 是泛词，有误伤风险

## 5. 实验四：小型大写排版导致的文本碎片

### 问题

论文标题常用 small caps 排版：「S」是大字、「ELF」是小一号，
在 PDF 里是两段独立文本，提取出来变成：

```
S / ELF / - / RAG / : L / EARNING TO / R / ETRIEVE
```

检索时 `SELF`、`RAG` 这些词被切成单字母，词项对不上。

### 做法

合并断行时加一条规则：**上一行 ≤ 3 个字符且无句末标点 → 直接拼接，不补空格**。

### 结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 46 题 Recall@1 | 91.3% | **93.5%** |
| 46 题 MRR | 94.6% | 95.7% |
| hold-out / 拒答 | 100% / 15% | 不变 |

### 局限

行内仍有 `C RITIQUE`、`S ELF` 这类碎片（字体层面字距问题）。
修它要改 TJ 空格判定阈值，风险是吃掉正常词间距，收益小，暂不处理。

## 6. 四个实验合起来

| 阶段 | 46 题 Recall@1 | 说明 |
|---|---|---|
| 起点（BM25 + 200/60） | 84.8% | 基线 |
| + 别名加权 | 91.3% | 解决「问原文、答综述」 |
| + 小型大写修复 | **93.5%** | 解决词被切碎 |
| 拒答误答率 | 55% → **15%** | 独立维度 |

## 7. 诚实的边界

| 做不到 | 原因 |
|---|---|
| 中文提问查英文论文 | 词面匹配对不上，需要翻译或跨语言向量检索 |
| 回答像人写的 | 抽取式只会摘句子，组织语言需要 LLM |
| 判断引用真的支持结论 | 需要 NLI 模型或 LLM judge |
| 扫描件 | 没有 OCR |
| 多用户隔离 | 只有浏览器会话级隔离，没有账号体系 |

## 9. 如果重做，会改什么

1. **先建评测集，再写检索**。我是先写代码后补评测的，前期调参全靠感觉
2. **更早做拒答**。误答比检索不准更伤害信任
3. **不要手调阈值**。应该用同一套特征训练一个轻量分类器，或者接 LLM 判断
4. **账要早算**。每次实验都该记录耗时和成本，否则不知道「好用」还是「只是能跑」
